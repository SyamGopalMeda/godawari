# 11. Verified Ghats, Bathing Centres and Facilities

The application now uses **real, attributable location data** instead of the synthetic demo site. This document records where every location comes from, how it was verified, what is not yet available, and how the control room validates and updates data.

## 11.1 Principles

1. **No invented positions.** Every coordinate comes from a public, attributable source (OpenStreetMap) or from an administrator who confirms it. A place named in a written source but not located has **no coordinates**. It is listed with "Location not verified", is never placed on a map and is never routed to.
2. **No fabricated operational data.** The real dataset contains no crowd readings, capacities, alerts, festival gates, festival parking zones, help desks, changing rooms or wristband detections. The app shows "No verified crowd data" and "Not yet published by the organisers" until real devices or the organisers provide them.
3. **Provenance on every record.** Each location stores `source`, `source_ref` (link), `source_retrieved_at`, `verification`, `verified_by`, `verified_at` and `verification_note`, and the app shows them on the place detail page.
4. **The control room is the authority.** Records an admin has verified or edited are never overwritten when the public dataset is refreshed.

## 11.2 Verification levels

| Level | Meaning | Map pin | Directions |
|---|---|---|---|
| `official` | Confirmed by the organisers or an admin in the control room (with note and source) | Yes | Yes |
| `source` | Position from OpenStreetMap, not yet confirmed by the organisers | Yes, badge "Map source (OpenStreetMap)" | Yes |
| `unverified` | Named by a reliable written source; position unknown | **No** | **No** (API returns 409) |
| `unavailable` | Closed, removed or not usable (place is also set to closed) | No action offered | No |
| `demo` | Synthetic data used only by automated tests (`PUSHKAR_SEED_MODE=demo`) | Test only | Test only |

**Rejected during review:** "Lanchela revu" near Kovvur is an untagged OSM point whose name means a boat landing. It is not evidence of a bathing ghat. The import rule now accepts "revu" only when OSM tags it as a bathing or tourist place.

**Known gaps:**
- OpenStreetMap has almost no ghat-level mapping on the Godavari, and few public toilets, drinking-water points or parking areas.
- Changing rooms, help desks, lost and found, festival gates and festival parking are not mapped anywhere.
- These gaps are shown to pilgrims as "Not yet published by the organisers" or "None mapped nearby", never filled with guesses.

**Correction to earlier versions.** The v1 and v2 demo placed "Pushkar Ghat" about 1 km away from its OpenStreetMap position. All demo positions have been removed from the default installation.

## 11.5 How it works in the app

- **Ghats & bathing centres** (`/ghats`) lists centres by state, upstream to downstream, with search in Telugu, Hindi and English. Each centre shows its mapped and listed ghats, facility count and OSM source. On desktop a map sits beside the list.
- **Place detail** (`/places/:id`) is available for every ghat and facility. It shows:
  - names in three languages, a verification badge and the source link;
  - the position with a map, coordinates and distance, or "Location not verified";
  - crowd status only when a verified reading exists;
  - nearby facilities grouped by type, with honest empty states;
  - walking directions in the app, "Open in Maps app" and a link to OpenStreetMap.
- **Explore map** shows pins for mapped places only. Its search covers all places, including unmapped ones, which link to their details.
- **Walking directions** use the organisers' walkway graph when one is published; that route is crowd-aware and respects closures and accessibility. Otherwise they use OpenStreetMap footpaths through OSRM, and the route panel says crowd avoidance and step-free routing are not available. If the routing service is down, the app offers the phone's Maps app.
- **Search** covers names in Telugu, Hindi and English, codes and town names.

## 11.6 Control-room workflow (`/admin/locations`)

1. Filter by centre, type, verification level or "missing position".
2. Open a place. Edit names in three languages and the type, set the position by clicking the map or typing coordinates, and set open, accessible and capacity. Moving an `official` location resets it to `unverified`, so it must be re-confirmed.
3. Set the verification level with a required note and source (for example "District engineer survey, 12 Mar 2027"). `official` and `source` require coordinates; `unavailable` closes the place.
4. Use "Add location" to add organiser-published ghats, gates, parking zones, help desks and changing rooms as they are announced.
5. Every change is written to the audit log (`location.update`, `location.verify.*`, `location.create`).

API: `GET /sites`, `GET /locations` (q, site_id, state, type, types, verification, has_coords, near), `GET /locations/{id}`, `GET /locations/{id}/nearby`, `POST /locations` (admin), `PATCH /locations/{id}` (staff), `POST /locations/{id}/verification` (staff).

## 11.7 Refreshing the public dataset

```bash
cd backend
python scripts/import_osm.py          # queries Nominatim + Overpass politely, writes data/godavari_locations.json
# restart the API: new records are inserted, 'source'/'unverified' records refreshed,
# admin-verified or admin-edited records are kept as they are
```

`PUSHKAR_SEED_MODE=real` is the default and is used in Docker. `demo` loads the synthetic test site, used by the automated tests. `none` loads nothing.

## 11.8 Tests

`backend/tests/test_verified_locations.py` checks the following:
- The committed dataset has a source on every record. Unverified places carry no coordinates, and Pushkar Ghat matches its OSM node.
- Loading the real dataset creates no crowd readings, alerts or devices.
- Reloading never overwrites admin-verified records.
- Unmapped places are listed and sorted last, but never routed to (409).
- Search works in all three languages and site counts are correct.
- Nearby groups are distance-sorted and include empty groups.
- Verification requires coordinates and is audited.
- Walking routes fall back to OSRM, and a routing outage returns 503.
